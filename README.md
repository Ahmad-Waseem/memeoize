# Meme Agent — Context-Aware Meme Generation

## Who has this problem?

Anyone who wants to make a personalized meme — dropping their own photo (or a
friend's) into a trending template — but existing tools only do one of two
things badly:

1. **Static meme generators** (ImgFlip, MemeGenerator-style bots, including
   Slack/Discord meme bots) support template + text overlay only. They can't
   place a real reference photo into a template's actual composition.
2. **Raw image-generation models** (used directly) *can* composite a photo
   into a scene, but only if the user writes a precise, well-structured
   prompt — most casual requests ("put this face on the drake guy") are
   underspecified, and a naive one-shot prompt to the model often produces
   misplaced faces, wrong scale, or lost likeness.

## What bottleneck makes it worth solving?

There's no tool that takes a casual, underspecified request and reliably
turns it into a well-composed meme. The gap is entirely in the *reasoning*
step between "what the user meant" and "what the image model needs to be
told" — plus nothing checks whether the output actually succeeded before
handing it back.

## Does the agent solve it well?

The pipeline adds three reasoning steps a naive approach skips:

1. **Understand intent** — parses the casual request (+ optional reference
   image) into structured intent: which meme format, what role the
   reference image plays, what composition/text is implied.
2. **Engineer the edit prompt** — translates that structured intent into a
   precise, well-composed prompt for the image model — the part most users
   can't do well themselves.
3. **Verify and retry** — checks the generated image against the original
   intent (correct placement, undistorted likeness, requested text present)
   and retries with corrective feedback (max 2 attempts) if it fails.

See `/eval/eval_results.json` (generated by running `eval/eval.py`) for the
baseline-vs-agent comparison on a fixed 10-case test set.

## Architecture

```
POST /webhook/meme-agent { text, image? }
        |
        v
  [Understand Intent LLM] --safety_flag=needs_review--> [Decline, explain why]
        |  safety_flag=none
        v
  [Engineer Edit Prompt LLM] <----------------------+
        |                                            | (retry, max 2x,
        v                                            |  with feedback)
  [Generate Image — Gemini/Nano Banana]               |
        |                                            |
        v                                            |
  [Verify Output LLM (vision)] --verdict=retry-------+
        |  verdict=pass
        v
  Respond { image, retries_used, verdict }
```

**Baseline** (`workflows/baseline.json`): raw user text (+ image) forwarded
directly to the image model — no intent parsing, no prompt engineering, no
verification. This is what a naive "AI meme bot" looks like.

## Safety boundary

The agent explicitly refuses to generate or edit images that would depict a
minor being composited/face-swapped, regardless of meme format popularity or
how the request is framed. This is enforced in the intent-understanding
step (`prompts/01_understand_intent.md`) before any image generation is
attempted — see the `safety_flag` field.
